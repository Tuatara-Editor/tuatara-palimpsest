#+title: What palimpsest is
#+language: en

* What palimpsest is

A package that takes a PDF apart, save by save, and looks for signs of editing.

A palimpsest is a page that was written over: the old writing is scraped off,
and it still shows under the new. A PDF is often like that. When a program
changes a finished PDF it can add the change at the end of the file and leave
what was there before, so the earlier text is still in the file. Other edits
leave other traces: a date that cannot be right, a white box over a figure, a
character copied over another in a scan. palimpsest reads a PDF, or a picture of
a scanned page, and reports each save the file holds and every such trace.

It is a package, not part of the editor, and it is for people who must judge
whether a document is what it says it is. This chapter says how to load it, what
it reads, what it never does, and how much a finding can be trusted. The
chapters after it cover each part of the report and each check.

** Loading it

palimpsest is loaded like any package, with a line in your init file:

#+begin_src lisp
(load-package "palimpsest"
              :source "https://github.com/Tuatara-Editor/tuatara-palimpsest")
#+end_src

Save the file and start Tuatara again. Tuatara fetches the package the first
time, offers to show you its source and asks whether to compile and load it.
Answer ~y~. After that it loads at every start. Chapter 19 of the main manual
explains packages, signatures and updates.

To read scanned pages palimpsest needs three programs on the machine:
bubblewrap, ImageMagick and poppler. On Fedora they are in the packages
=bubblewrap=, =ImageMagick= and =poppler-utils=. A PDF with no scanned page
needs none of them.

** What it reads

palimpsest reads the octets of the file, with its own code. Octets are the bytes
of the file. It does not hand the PDF to another program to open, and it follows
the PDF's own structure: the cross-reference sections, which say where each
object begins, the trailers, the objects and their streams, the pages and what
they draw.

It examines two kinds of file:

- a PDF, taken apart into its saves, which the report calls revisions;
- a picture file (PNG, JPEG or TIFF), examined as one scanned page. A picture
  has no revisions, so the commands that write or show a revision say so
  (~C-c o~, ~C-c w~, ~C-c t~ and ~C-c T~). Its summary gives its kind
  and its size in pixels in place of a PDF version, and its =* Checks= lists
  only the checks of a scanned page. ~C-c s~ still saves the report and the
  fingerprint.

A place on a PDF's page is given in points from the page's bottom left. A place
on a picture is given in the same points, one point to a pixel, and in pixels
from its top left.

** What it never does

Nothing in a file is run. JavaScript, actions that launch programs and addresses
to visit are named in the report and never followed. Nothing the file names is
fetched. The file is not changed, and nothing is written beside it: what
palimpsest writes goes to a directory of its own in Tuatara's cache directory,
readable by you alone. A directory named in
=*evidence-directories*= refuses every write, as the main manual's chapter 12
says, so nothing palimpsest makes can land in one.

The file itself is read in a Tuatara of its own, shut in a sandbox, a wall
that lets a program read what it is given and write nowhere else. That Tuatara
has a limit of memory and of time, so a file made to fill the memory stops
there and never ends the editor (chapter 9). Pictures in a scanned page are
decoded there too, each by a program held to its own files. A page kept as
fax or JBIG2 is drawn by poppler's =pdftoppm= in the sandbox, from a PDF of that
picture alone. Only the pictures of scanned pages are decoded; no page is ever
drawn as a picture to be compared.

What the report quotes from the file, such as a producer, a signer's name or
text from a page, is written with each control character shown as Tuatara shows
it on the screen, an escape as =^[= and a bell as =^G=. Reading a kept report
with =cat= in a terminal cannot move the cursor or hide a line, whatever was
written into the PDF.

** A sign is not proof

Every finding says that something in the file looks like a trace of editing.
None of them says who edited the file, or that the edit was wrong. Honest files
have later saves, programs that edit PDFs, fonts in two subsets, scans with
uneven ink. Each finding names the honest causes it knows, so that you can weigh
them. Chapter 6 says how the strengths are given and how to read a finding.

Two things palimpsest cannot do, and you must not expect of it:

- find an earlier save that was erased without trace. A file written again in
  one go, with nothing of the old text in it, has no earlier save to read;
- say that a file is genuine. "No sign of editing found" means that none of its
  checks found one, and a careful hand leaves few.

Chapter 9 lists the other limits, and chapter 7 what each check can and cannot
tell.

#+begin_try Try it, loading palimpsest and opening a report
1. Add the =load-package= line above to your init file with ~C-x C-f~ on
   =~/.config/tuatara/init.lisp=, and save it with ~C-x C-s~.
2. Restart Tuatara. To the question about compiling and loading palimpsest,
   press ~v~ to read its source, ~q~ to come back, then ~y~.
3. Open a PDF of your own with ~C-x C-f~.
4. Run ~M-x palimpsest~. A buffer named after the file opens and says it is
   examining. In a moment the report replaces that text. Chapter 2 reads it.
#+end_try
